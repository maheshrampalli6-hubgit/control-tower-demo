# ABC Inc. Delivery Control Tower — demo app

A working demo of the MVP from the assignment: **performance monitoring, real-time tracking and analytics** for a parcel company's intercity and intracity deliveries.

> ABC Inc. is fictional. Every number is generated by a built-in simulator: 16 regions / sorting hubs, 1,000 hubs, 1,000 delivery associates (DAs), 200 vehicles (100 owned, 100 hired). The simulated clock runs 2 minutes every 5 seconds, so the data keeps moving while you demo.

## What's in it

| Screen | User | What it shows |
| --- | --- | --- |
| **Overview** `#/ceo` | CEO | On-time delivery, cost per parcel, volume vs plan, damage rate, 12-week trend, region heatmap, owned vs hired fleet, top 3 risks |
| **Live network** `#/ops` | Operations Head | Live map of all 200 vehicles coloured by status, critical alerts, regional leaderboard, vendor scorecard |
| **Region** `#/region/CHI` | Regional Manager | Inbound line-haul lane board vs the sort cut-off, hubs ranked worst first, vendor scorecard, failure reasons, 12-week trend |
| **Hub** `#/hub/CHI-H001` | Hub Manager | Shift progress, each DA's progress vs plan, alerts, late inbound trucks, failed deliveries by reason |
| **Trip** `#/trip/T-1001` | Ops / Regional | Route planned vs driven, milestones, ETA vs cut-off, downstream impact |
| **Parcel tracker** `#/parcel/<id>` | Everyone | The 7-event journey of a parcel across intracity and intercity legs |
| **Alerts** `#/alerts` | Hub / Regional | Alert inbox with acknowledge / resolve and automatic escalation (30 min → Regional Manager, 60 min → Ops Head) |
| **Product KPIs** `#/product` | Product team | The 3 weekly engagement KPIs (weekly active managers, alert action rate, drill-down depth) plus live counts from your session |

**Things you can click in a demo:** switch the "Viewing as" role, drill CEO → region → hub → DA, click a delayed truck on the map, acknowledge or resolve an alert, **Reassign stops** from a slow DA, **Assign** unassigned stops when a DA is absent, **Call driver** on a delayed trip (its stop clears faster), search by parcel ID, vehicle (`TRK-012`, `HIR-031`), hub (`CHI-H001`) or region code (`MIA`).

## Run it locally (2 minutes)

Requires Node.js 18 or newer.

```bash
npm install
npm start
# open http://localhost:3000
```

Check every API endpoint while it runs:

```bash
npm run smoke
```

## Deploy on AWS EC2

### 1. Launch the instance
1. EC2 console → **Launch instance**.
2. AMI: **Amazon Linux 2023** or **Ubuntu 24.04 LTS**.
3. Instance type: **t3.micro** or **t3.small** is plenty (the app uses ~80 MB RAM).
4. Key pair: create or pick one (you need it for SSH).
5. **Security group** inbound rules:
   - SSH, port 22, source **My IP**
   - HTTP, port 80, source **Anywhere (0.0.0.0/0)**, or your interviewers' IPs only
6. Launch and copy the instance's **Public IPv4 address**.

### 2. Copy the app to the instance
From your computer, in the folder that contains the zip:

```bash
# Amazon Linux user is ec2-user; on Ubuntu use ubuntu@
scp -i your-key.pem control-tower-demo.zip ec2-user@<PUBLIC_IP>:~
ssh -i your-key.pem ec2-user@<PUBLIC_IP>
```

On the instance:

```bash
sudo dnf install -y unzip   # Ubuntu: sudo apt-get install -y unzip
unzip control-tower-demo.zip
cd control-tower-demo
```

### 3a. Option A: one-command setup (Node + systemd + nginx) — recommended
```bash
sudo bash deploy/ec2-setup.sh
```
To protect the demo with a username and password:
```bash
sudo DEMO_USER=demo DEMO_PASS='pick-a-strong-password' bash deploy/ec2-setup.sh
```
The script installs Node.js 20 and nginx, copies the app to `/opt/control-tower`, runs it as a systemd service on port 3000, and puts nginx in front on port 80. When it finishes it prints the URL: `http://<PUBLIC_IP>/`.

Useful commands:
```bash
sudo systemctl status control-tower     # is it running?
sudo journalctl -u control-tower -f     # live logs
sudo systemctl restart control-tower    # restart (also resets the simulated day)
```

### 3b. Option B: Docker
```bash
# Amazon Linux 2023
sudo dnf install -y docker && sudo systemctl enable --now docker
sudo usermod -aG docker $USER && newgrp docker
# docker compose plugin (Amazon Linux 2023)
sudo mkdir -p /usr/local/lib/docker/cli-plugins
sudo curl -SL https://github.com/docker/compose/releases/latest/download/docker-compose-linux-$(uname -m) -o /usr/local/lib/docker/cli-plugins/docker-compose
sudo chmod +x /usr/local/lib/docker/cli-plugins/docker-compose

docker compose up -d --build
# with a password:  DEMO_USER=demo DEMO_PASS='...' docker compose up -d --build
```
Open `http://<PUBLIC_IP>/`.

### Troubleshooting
| Symptom | Fix |
| --- | --- |
| Browser times out | Security group is missing the HTTP port 80 inbound rule |
| `502 Bad Gateway` | App not running: `sudo journalctl -u control-tower -n 50` |
| Map is grey | The browser can't reach the map tile server (CARTO / OpenStreetMap); everything else still works |
| Want a faster or slower day | Edit `TICK_MS` / `SIM_MINUTES_PER_TICK` in `/etc/control-tower.env`, then restart |

**Cost tip:** stop or terminate the instance after the interview. A t3.micro is free-tier eligible for new AWS accounts.

## How it works

```
 Simulator (src/sim.js)          API (src/api.js + server.js)         Dashboard (public/)
 ───────────────────────          ────────────────────────────         ───────────────────
 16 regions, 1,000 hubs,   ──▶    One metric dictionary: OTD,    ──▶  Role-based screens,
 1,000 DAs, 200 vehicles          first-attempt success, backlog,      live map (Leaflet),
 trips move every 5 s,            cost per parcel, line-haul           charts (Chart.js),
 incidents, idle DAs,             on-time, alert rules +               refresh every 5 s,
 absences, alerts                 escalation, user actions             actions POST back
```

- **No database.** State lives in memory and is regenerated from a fixed seed on restart (`SEED` env var), so the demo is repeatable.
- **Same numbers everywhere.** Every view is computed by the same helper functions, so the CEO's network figure is the sum of the regions, which is the sum of the hubs.
- **Alert rules:** line-haul delayed 30+ min, line-haul will miss the sort cut-off, DA idle 30+ min, hub backlog over 120 parcels. Alerts auto-resolve when the condition clears.
- **Front-end libraries** (Leaflet, Chart.js) are served from `node_modules`, so no CDN is needed. Map tiles and the Inter font load from the internet.

### API
| Method | Path | Purpose |
| --- | --- | --- |
| GET | `/api/health` | Health check |
| GET | `/api/meta` | Regions, hubs for the selectors, sample parcel IDs |
| GET | `/api/ceo` · `/api/ops` | CEO and Operations Head views |
| GET | `/api/regions/:id` · `/api/hubs/:id` · `/api/trips/:id` · `/api/parcels/:id` | Drill-down views |
| GET | `/api/alerts?severity=&regionId=&hubId=` | Open alerts |
| GET | `/api/search?q=` | Find a parcel, vehicle, trip, hub or region |
| POST | `/api/alerts/:id/ack` · `/api/alerts/:id/resolve` | Act on an alert |
| POST | `/api/das/:id/reassign` · `/api/hubs/:id/assign-unassigned` · `/api/trips/:id/contact` | Field actions |
| GET | `/api/product-kpis` | Weekly engagement KPIs |

## Suggested 5-minute interview demo
1. **Overview (CEO):** "On-time is below target. Which region?" Click the worst region tile.
2. **Region (Regional Manager):** point at the lane board. "This truck will miss the 23:00 sort cut-off." Show the hub ranking and the hired vendor at the bottom of the scorecard.
3. **Hub (Hub Manager):** a DA is behind. Click **Reassign stops** and watch the bars change.
4. **Live network (Ops Head):** filter to **Delayed only**, click a red truck, then **Call driver**.
5. **Alerts:** acknowledge one and explain escalation.
6. **Product KPIs:** "This is how I'd know the product is actually used." Your actions show up live.
